# `deprecated_stale_eval/` — quarantined contaminated evaluation artifacts

**Do not reuse these for any number that goes in the paper.** They are kept only as
forensic evidence for the race-gap correction. Authoritative source of record:
`Task10/results/*_test_predictions.csv` (fixed-split predictions), evaluated via
`analysis/corrected_eval.py`. Full provenance: `outputs/race_gap_provenance.md` and
`outputs/seed_provenance_confirmation.md`.

These files were `git mv`-ed here (history preserved) so the stale evaluation path fails
loudly instead of silently regenerating wrong numbers.

## Why each item is deprecated

- **`Task6/results/` (entire directory: 38 `*_disparity_summary.csv`, 38
  `*_subgroup_metrics.csv`, `fairness_gap_summary_by_model.csv`,
  `all_model_disparity_summaries.csv`, `task6_final_summary.csv`, 3 `task6_*.png`).**
  Generated by `Task8/run_validation.py`, which couples the train/test **split seed to the
  model seed** — `prepare_for_seed(X_raw, M, y, ids, args.seed)` (run_validation.py:141)
  → `DataPipeline.split_data(random_state=seed)` (DataPipeline.py:345). Each seed therefore
  scored a *different* cohort (race counts drift: Asian 182/170/179). The paper's headline
  race gaps (LSTM 0.1352, TGTFull 0.1291) come from averaging these per-seed-resplit gaps;
  on the matched fixed split the ordering reverses (LSTM 0.1847 < TGTFull 0.2090). Moving
  the whole directory severs the regeneration chain
  subgroup_metrics → aggregates → final_summary.

- **`Task9/Task9Results/T9_predictions_cache.pkl`.** Built under a hardcoded scalar
  `seed = 42` lock (`Task6/config.py:14` and `Task9/runfile.py:21,32` @ commit `b81d34f`),
  so it is a **seed-42-only artifact for both models**, not the 3-seed average its current
  runfile header claims. Quarantining it forces `Task9/runfile.py` to rebuild (via the
  current multi-seed loop) instead of reusing the locked cache.

## Not moved (deliberately)

`Task6/results_T6/` is a separate `SimpleModelEval` output directory that never fed the
paper tables; it stays in place. `analysis/corrected_eval.py` does **not** read the Task9
cache, so the corrected results are unaffected by this quarantine.
